# V7 — consolidated evidence and a local battle demonstration

V7 is the final planned milestone. It packages supported V1–V6 work; it does not
rerun experiments or turn incomplete acceptance into success. Both V6 attempts
remain incomplete. The preserved pre-V7 status is [MILESTONE6-REPAIR.md](MILESTONE6-REPAIR.md),
SHA-256 `cd6e9590e617701aca4089c68a029a465446790ca4bf43757c0527a85dbc5b29`.

## Watch locally

From the project root, after setup and retaining/importing the bundle:

```powershell
.\scripts\start-demo.ps1 -Bundle runs/v7-release-bundle -Output runs/MY_FRESH_DEMO
# Open http://127.0.0.1:8765
# Stop from another terminal, or press Ctrl+C in the first terminal:
.\scripts\stop-demo.ps1 -Run runs/MY_FRESH_DEMO
```

The viewer offers Play/Pause, four pacing settings, previous/next turn, reset,
and go-to-turn. Select a normal V2 recording, the V5 choice-change example, the
V6 freeze cap, or four chronological V6 encounters. These examples explain
behavior; they are not a representative win-rate sample. The public battle log
uses the official renderer's English messages. Raw public protocol is optional.

The live selector offers RandomLegal, MaxBasePower, V2 heuristic, unchanged V4
switch-logistic, and the frozen selected V5 learned-score policy. Two games and
300 aggregate run seconds are the default ceiling; each game reserves 75 seconds,
uses a 60-second match timeout and the existing 300-turn cap. The service itself
stops after 30 minutes (CLI maximum one hour). All services use 127.0.0.1.

Simulation is usually faster than animation. Live recordings say **Delayed
playback — simulation may already be finished**. Pause/speed/turn controls are
browser-only and cannot delay decisions or feed information to agents. There is
no spectator command to submit a move. Terminal status is separate from playback:
completed, capped, timed out, failed, cancelled or not started. Cleanup forfeits
are stripped from incomplete viewer results and never count as ordinary wins.

V6 live cross-encounter adaptation is intentionally unsupported. The four ordered
recordings and the offline audit trace reproduce real memory updates from empty
memory; they are never presented as newly simulated live adaptation. To view
finished demo exports on a subsequent service without collecting games:

```powershell
. .\scripts\env.ps1
.\.venv\Scripts\python.exe -m battlemind demo-serve --bundle runs/v7-release-imported --recordings runs/v7-demo-verification/public --output runs/MY_FRESH_PLAYBACK --games 0
```

## The display boundary

`viewer_records.py` defines `v7-public-replay-1`. A separate anonymous spectator
WebSocket joins only the engine-generated room ID. Pinned Showdown `rooms.ts`
defines channel 0 as spectator/public HP, player channels as exact own HP, and -1
as debug/exact HP. The viewer never authenticates as a player. It accepts an
allowlist of mechanics messages, rejects private requests/split/team messages,
normalizes public account names to Side 1/Side 2, and withholds winner messages
until the runner's terminal accounting validates them.

The only addition to the existing player hook forwards a **room ID**, not that
player's messages, requests or policy. The existing per-player journals, legal
mapping, warnings and post-match commitment audit are unchanged. Installed
poke-env 0.16.1 message/request hooks were inspected before this change. The
spectator has no reference to an agent's snapshot, journal, policy or memory.

Historical V1–V6 runs did not save channel-0 replay streams. Their viewer export
aligns the two clients' chronological public projections, then takes each actor's
event only from the **opposing observer**. This retains public 100-scale HP and
revealed species/moves, never own exact HP. It reads the existing public-history
file in the recorder directory, not an engine end log. Alignment mismatches fail.
Missing effect annotations remain missing; the historical animation is explicitly
an incomplete public projection. It is not substituted for original audit evidence.

Optional explanations contain actual recorded **viewed-player** probabilities,
scores, alternatives and reasons. They become available only after an encounter.
They contain no snapshot, opponent private team, engine seed or current choice.
For example, V5 decision `m0:a:r2` had p=0.0812879: initial Switch 4 scored 115
versus Thunder Wave 95; selected parameters gave Thunder Wave 127.986 versus
Switch 4 at 101.806. This proves choice influence, not that the alternate loses.

HTTP serves an exact mapping of public replay IDs and pinned asset names. There
is no directory listing or arbitrary path endpoint. Models, memory-trace inputs,
private logs and source/licenses are not HTTP routes. Local JSON launch/stop
requests check Host, Origin and a service token. The token is a local control
guard, is stored only in ignored service output, and is never bundled. CSP rejects
external assets, fonts, audio, frames, forms and network connections.

## Official animation, local assets

The official battle renderer is from client commit
`afa9d4ae645923e42fc8f587080c6bf3d13de2fc`, inspected alongside its replay embed and
build scripts. The full account/login client is not included. The upstream embed
loads remote runtime files, so BattleMind supplies a local shell instead.

`scripts/setup-viewer.py` downloads **2,913,473 bytes** of official source, required
sprites/effects and notices. No full sprite archive, audio, model or dataset is
downloaded. Sources are commit-pinned; hosted sprite bytes are SHA-256 pinned in
`configs/viewer-assets.json`. `scripts/build-viewer.cjs` uses existing pinned
esbuild 0.25.12 for TypeScript erasure and the upstream global-script convention.
It routes renderer resources locally, publishes the Dex global required by effect
initialization, and supplies English text/Gen 1 display data from the pinned engine.
No simulator logic is added. Empty generation override tables are display plumbing
because the base data already comes from Gen 1. Other generations are rejected.

Battle renderer file headers license those components MIT; the full client is
AGPLv3. Both context and component notices/source are retained. jQuery and Caja
sanitizer notices stay in their files; effect artist credits stay in source.
Pokémon artwork belongs to its respective owners. See [ATTRIBUTION.md](ATTRIBUTION.md).

During UI development, syntax/global ordering, missing display tables, an effect
URL global and a scene-switch race were found and repaired before final playback
verification. Preliminary V7 bundles/checks remain in ignored output and are not
the release bundle. The renderer asset repair collected no additional games and
did not change any predictor, scorer, policy parameter, public-memory rule or outcome.

## Evidence catalog and audit scope

`python -m battlemind evidence --output runs/FRESH_EVIDENCE` reads nine retained
scopes. It recomputes terminal counts from all run manifests/battle records,
compares saved summaries, verifies original artifact manifests, and carries
forward probability metrics, exclusions, calibration support, group breakdowns,
uncertainty, schedules, policies/models, hashes, resources and audit coverage.
`catalog.json` is machine-readable; `REPORT.md` is the readable overview. Missing
fields are unknown, inconsistent fields are errors. No ranking pools incomparable
versions, phases or opponents.

Artifact integrity means retained bytes still match an original manifest. Semantic
replay means a stated audit reproduced decisions/labels/memory. Source compatibility
means the relevant implementation matches its freeze. These are separate. Full
historical source audits still reject changed current source; V7 does not weaken
them. The original predictor/checkpoint loaders still enforce exact scoring/feature
compatibility, and the bundle separately replays its complete four-encounter memory
prefix. V7's catalog does not claim to rerun every historical private audit.

Original V6 remains exactly **96 completed development games; development budget
exhausted; zero final games**. Its old final arm grid counts planned slots and its
failed-phase timing includes reporting; neither is rewritten. The repair retains
396 requested/395 completed/one cap/324 never requested. Only one final reset group
completed. Partial final probability metrics cover 248 games, whereas terminal
accounting includes 251 completed final games. These are different denominators
by the original complete-cell rule, not missing games to fill or losses to invent.
